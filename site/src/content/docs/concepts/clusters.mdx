Strata runs on [Apache Pekko](https://pekko.apache.org) cluster sharding. Entity ids hash to
shards, and shards are spread over the nodes. When a node stops (a deploy, a crash, a scale-down)
its shards move to the others, and each entity loads its committed state from the store on its
new node. A command that was running there resumes, as in [durable
invocations](../../concepts/durable-invocations/).

<Failover client:visible />

Tested: on two nodes, 40 entities split between them; one node leaves and all 40 answer from the
other with their state. On Kubernetes, deleting a pod loses no committed state, and
the replacement pod rejoins the same cluster.

## Joining

- **`strata.pekko.cluster-mode = single`** (default): one node, its own cluster.
- **`seed-nodes`** with `STRATA_SEED_NODES`: list every node. A restarted node then rejoins the
  others instead of starting a cluster of its own. The [Kubernetes guide](../../guides/kubernetes/)
  sets this up for you.

## When a node dies or the network splits

If nodes stop hearing each other, Pekko's split-brain resolver decides which side keeps running
(after `strata.pekko.split-brain.stable-after`), and the other side stops. Your data is safe either
way: every commit is fenced by revision, so two sides can't overwrite each other.

| `strata.pekko.split-brain.strategy` (`STRATA_SPLIT_BRAIN`) | Keeps the side that |
|---|---|
| `keep-majority` (default) | has more nodes. On a tie, the side with the lowest address. |
| `lease-majority` | holds a lease in Strata's store. The side that can't reach the store couldn't commit anyway. |

The tie matters more than it sounds. Tested on two nodes: when the node with the lower address
crashes, under `keep-majority` the **survivor stops itself**, a full outage from losing one node;
under `lease-majority` the survivor takes the lease, removes the dead node, and serves every
entity, including those that lived on the dead one. Use `lease-majority` for 2 nodes or any even
size; the Kubernetes manifests do by default.

Also tested on Kubernetes (minikube, PostgreSQL): freezing one of two pods mid-traffic, the other
took the lease after the 20 s stability window and served all 20 accounts within a minute,
including the ten that lived on the frozen pod; Kubernetes then restarted the frozen pod and it
rejoined with every balance intact.

A node that has been removed reports itself not live (`/strata/health/live` answers 503), so
Kubernetes restarts it and it joins again.

## Encrypting traffic between nodes

Entity calls travel between nodes, so in production encrypt them. With TLS on, nodes also
**authenticate each other**: a node joins only if it presents a certificate the others trust, so a
stranger on the network can't join the cluster (tested: a plain-TCP node is refused).

| `strata.pekko.tls.mode` (`STRATA_TLS`) | Certificates from |
|---|---|
| `off` (default) | none: plain TCP, for development |
| `keystore` | JKS or PKCS12 files: `STRATA_TLS_KEY_STORE`, `STRATA_TLS_TRUST_STORE` and their passwords |
| `pem` | A directory with `tls.key`, `tls.crt`, `ca.crt` (`STRATA_TLS_DIR`), reread as they rotate: what cert-manager writes |

Missing files or passwords stop the node at start with a message naming the setting. For `pem`,
the key must be RSA, the node certificate must be issued directly by a root CA, and all nodes'
certificates must share a subject name (CN or SAN). On Kubernetes, the [Gradle plugin](../../guides/kubernetes/)
mounts the certificate Secret for you.
